# 发布交付流程

老马已授权本项目持续采用以下流程，无需每次重新确认收件人和推送仓库。 执行前须完成项目级统一批次协调；持续部署授权不等于各任务可以自行单发，源码推送仍遵守老马最新暂停/恢复指令。

0. 先更新 [统一发布协调清单](RELEASE_COORDINATION.md)，由指定统筹会话收集各开发任务交接，盘点进行中任务、已完成未发布项和线上缺口。确认本批范围、关联依赖、文件冲突、集成验收与独立延期项；未盘点完整或关联任务未就绪不得生成候选。各任务不单独发包部署，不通过隔离副本绕过统发；仅老马明确指定的独立发布可例外。
1. 完成本批全部纳入任务的业务变更、浏览器验证和相关测试，核对服务器实际基线、跨模块契约及迁移顺序。集成验收通过后冻结统一源码，逐项核对批次任务与候选文件清单，只生成一个正式候选。冻结后新改动列入下一批；影响当前批依赖或安全时先暂停并重审。
2. 入口改用 `release-tools/publish-project.ps1 -ReleaseId <版本> -AuditFile <审计路径>`。它顺序执行原打包器的完整性、安装及健康门禁，再调用 `deliver-project.cjs`，以飞书应用身份给马进宇发送 ZIP。
3. 发包脚本核对 CLI 应用身份、正式包验收状态与 SHA-256；在 `.runtime/release-delivery/<版本>.json` 持久化发送状态、幂等键和消息回执。失败或发送结果不明时停止，核实消息后再恢复，不自动循环重发。
4. 飞书返回发送成功后，只删除该版本的外层正式 ZIP 和内层重复 ZIP。保留冻结 payload、清单、哈希和验收证据，用于后续基线及回滚验证。这些材料不进 Git。
5. 2026-10-31 起，老马授权由本项目通过 SSH/SFTP 和独立 PowerShell 任务部署（包括20261031.1）。固定项目目录 `C:\ai\overseas-project-management-deploy-20260605-163554`，仅操作3333对应进程。上传前后校验正式候选身份、清单及实际文件哈希；先只读检查实际版本、配置、待同步台账、旧事务和恢复目录，再切换。凭据不随包上传，不重装依赖或在服务器构建。
6. 远程实测安装、可信HTTPS、网页资源、数据保留均通过，且部署任务结束后从独立 SSH 会话复查进程和健康、间隔至少60秒再次通过后，发送结束卡片。先将实际结果记录到 `docs/releases/<版本>.json`；收到“部署成功”后再推进 `docs/releases/current.json`。失败保留恢复材料并验证回滚；仅有发包回执、本机验收或旧 success.json 不推进生产基线。
7. 2026-11-02 老马确认后续部署验收成功即自动归档到 `https://github.com/frankmjy/Overseas-Cross-regional-Horizontal-Platform` 的 `main`，无需再单独确认源码推送。归档从该候选冻结源码和对应发布工具、测试取材，不直接提交混有未部署改动的当前工作区；保留版本号、候选SHA-256与提交SHA的对应关系，提交脱敏版本记录，正常快进推送后回读远端提交确认成功。服务器部署成功、GitHub归档成功和人工基线确认是三个独立状态。登录/权限缺失、远端分叉或推送回执不明时保留待归档状态，先核对，不强推、不把服务器部署报告成失败，也不声称归档完成。此前暂停推送的历史版本不自动补推；本轮暂停部署仍有效，本约定不是立即部署或立即推送当前工作区的指令。

仓库为公开仓库。仅提交应用源码、测试、公开部署模板和工具；`.env`、私钥、证书、账号配置、生产账本、调研内容导出、截图、报告及 ZIP 均排除。飞书应用和收件人使用用户已确认的应用内稳定标识，跨应用必须重新核对。

2026-10-26 按用户确认，海外平台当前应用改为“定盘星” `cli_aa547c8de6785ce2`。发包收件人在此应用下为马进宇 `ou_cc9fe24c613ded770d74f7495b575a3c`；映射由新应用读取同一正式登录记录的人员关联、姓名及旧标识交叉核对。当前绑定集中保存于 `auth/application.json`。旧应用和旧收件人的配对仅允许验证既有回执，历史回执不重写、不因迁移重复发包。新发送必须核对 CLI 当前应用与新绑定一致。

安装器、发布框架或依赖变化时，继续按项目安全门禁重新取证；交付脚本不替代预检，不更改候选和安装器字节。

更新通告使用 `release-tools/notify-release.cjs` 和 `release-tools/release-notifications.json`。 每个统一发布批次只发一组开始/结束或失败通告，各开发任务不分别发送版本卡；卡片列出本批实际包含的任务，延期项继续保留在统一清单。正式开始前发蓝色卡，远程验收成功后发绿色结束卡，失败发橙色卡并如实写明恢复状态；字段包含版本、类型、周期、更新内容和回退版本。开始卡不放访问入口，结束卡附访问按钮。2026-10-31 老马确认通告群为 `oc_6ad778f4d92599a395ee06c5c8ed2b8f`；首次私发预览已完成；后续默认发指定群，仅在老马明确要求时改为私发预览。通知写入持久化幂等台账，结果不明时核实后再恢复，禁止重发碰运气。

自动部署时，发布入口加 `-PrepareRemote`，在发包清理 ZIP 前先把同哈希内层包暂存并完成服务器只读预检和上传。随后运行 `deploy-remote.py start --release <版本> --notice-file <本次通知JSON>`，状态查询 `deploy-remote.py status --release <版本>`。通知文件必须提供本次版本及1–5条业务更新，禁止沿用上次内容；本次预览加 `--notification-preview`，后续默认发指定群。失败候选禁止复用为新候选的基线。

SSH凭据配置入口为 `release-tools/Configure-RemoteDeploy.ps1`；本机专用启动文件存放在忽略提交的 `reports/remote-deploy/`。首次从可信服务器控制台核对主机指纹，密码通过隐藏输入后使用当前Windows用户DPAPI加密，目录ACL只允许当前用户及SYSTEM。后续部署读取本机密文；主机密钥变化、解密失败或登录失败即停止，不自动换账号、换主机或重置凭据。

证书中心换证验收：已启用统一 TLS 中心时，安装器按中心 current.json 与不可变 fullchain.pem 的哈希、域名及有效期核对当前指纹，HTTPS 仍校验可信链与域名；未启用中心时保留原基线指纹。发布预检的真实安装与回滚夹具必须让审计旧指纹不同于中心当前证书，不能只测试两者相同的场景。证书来源在同一次安装中变化时应中止，禁止从网络返回值学习新指纹或跳过 TLS 校验。

- 新增外部适配器必须使用实际随包CLI/运行时及服务身份验证身份、字段和记录读取；不能只用本机另装版本。通用HTTPS健康不代替业务数据源就绪，业务回读和线上页面均通过后才发送成功通告。
