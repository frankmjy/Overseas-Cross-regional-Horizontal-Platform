# 发布交付流程

老马已授权本项目持续采用以下流程，无需每次重新确认收件人和推送仓库。

1. 完成业务变更、浏览器验证和相关测试，核对当前已部署基线。运行既有预检并冻结源码，只生成一个正式候选。
2. 入口改用 `release-tools/publish-project.ps1 -ReleaseId <版本> -AuditFile <审计路径>`。它顺序执行原打包器的完整性、安装及健康门禁，再调用 `deliver-project.cjs`，以飞书应用身份给马进宇发送 ZIP。
3. 发包脚本核对 CLI 应用身份、正式包验收状态与 SHA-256；在 `.runtime/release-delivery/<版本>.json` 持久化发送状态、幂等键和消息回执。失败或发送结果不明时停止，核实消息后再恢复，不自动循环重发。
4. 飞书返回发送成功后，只删除该版本的外层正式 ZIP 和内层重复 ZIP。保留冻结 payload、清单、哈希和验收证据，用于后续基线及回滚验证。这些材料不进 Git。
5. 等老马明确回复“部署成功”，登记 `docs/releases/<版本>.json` 与 `docs/releases/current.json`，标注用户确认（非远程实测）、版本和包 SHA-256；然后推送该候选对应源码到 GitHub main，并核对远端 commit。

仓库为公开仓库。仅提交应用源码、测试、公开部署模板和工具；`.env`、私钥、证书、账号配置、生产账本、调研内容导出、截图、报告及 ZIP 均排除。飞书应用和收件人使用用户已确认的应用内稳定标识，跨应用必须重新核对。

安装器、发布框架或依赖变化时，继续按项目安全门禁重新取证；交付脚本不替代预检，不更改候选和安装器字节。
