# 议事航迹｜会议助手同步指令

请把以下规则配置到有授权的会议助手。会议结束且有可核对的会议资料后，按记录 ID 更新飞书多维表。只在明确判断归属、会议信息和行动项后写入。权限不足时报告具体表和动作。

## 2. 会议字段

| 字段 | 写入规则 |
| --- | --- |
| Meeting Title（会议名称） | 使用原会议主题，去掉录音工具附加的时间或文件后缀 |
| Meeting Type（会议类型） | 项目例会、区域例会、专题评审、客户沟通、协调会，按主要目的单选。例会为固定节奏，评审有明确评审对象，客户沟通以与客户沟通为主，协调会处理跨团队协作。证据不足时留空并请求确认 |
| Meeting Date（会议日期）、Meeting Time（会议时间） | 用实际开会时间，统一换算北京时间。时间文本使用 HH:mm |
| Status（状态） | 确认实际召开后用表内「已开」。计划状态沿用已有选项 |
| Summary（会议概要） | 保留议题、主要结论和已明确的决定 |
| Participants（参与人） | 使用定盘星应用下核验的飞书人员身份，人员有同名或映射不明时留空待核 |
| Minutes Link（纪要链接）、Recording Link（妙记链接） | 分别写真实 HTTPS 纪要地址和妙记地址，缺少哪项就留空 |
| Priority（优先级） | 仅在有明确依据时使用表内选项 |
| Assistant Meeting ID（助手来源会议ID） | 以「来源系统:稳定会议ID」写入，同一会议重复同步使用同一个值 |
| Action Items（待办事项） | 保留已有历史文本。新待办优先写入独立待办表 |

## 3. 如何关联个人待办

打开[会议待办](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblrUCVFXhyql7gJ)，一项可执行的行动建一条记录。

1. 填写「待办事项」，用可验收的动作描述。
2. 「负责人」选对应的飞书人员，只填明确承担该事项的人。缺少负责人时留空，并在同步结果提醒补齐。
3. 「截止时间」填写明确约定的日期和时刻，按北京时间写入。仅约定日期时保留日期信息到备注，并提醒补充时刻。
4. 「状态」按已知进展填写待办、进行中或已完成。已完成仅在有明确结论时填写。「优先级」只用明确的 P0、P1、P2。平台重要待办显示尚未完成的 P0、P1。
5. 根据上表选择对应的**一列会议关联**，选刚写入或已经存在的原会议记录。关联字段传会议的飞书记录 ID，其他两列留空。保存后回读确认关联指向同一场会议。
6. 备注可填写验收要求或尚待确认的问题。重复同步时保留人工已更新的负责人、截止时间、状态和优先级，除非新资料明确纠正且需要更新。
7. 「Assistant Action ID（助手来源待办ID）」写入稳定的来源事项标识。如果来源没有事项 ID，助手第一次拆分时生成并持久保存一个编号，后续沿用该编号。

## 4. 重复同步与回读

- 同一来源会议只允许一个同步任务写入。先按「助手来源会议ID」精确查询三张会议表，查到一条则用记录 ID 更新。查到多条、或记录所在表和本次项目判断冲突时，交人工确认。首次接入既有会议，可再核对原有纪要或妙记链接。证据唯一时复用该记录并补来源 ID。
- 新建会议前持久保存来源标识和提交键。写入回执不明时先查同一来源、链接或提交标识；查不到仍保留待核对状态，下一次继续查同一个提交。
- 待办先按「助手来源待办ID」精确查询，再核对是否关联同一会议。命中唯一记录时更新原待办。关联冲突或命中多条时交人工核对。
- 写入后回读，确认会议字段、待办负责人、截止时间和关联列。同步结果返回会议记录链接、已新增和已更新的待办数量，以及需要人工确认的事项。无权读取或回读失败时说明实际状态。

## 后台结构复核

保留泰国、马来及海外同频三张原表，沿用项目归档、记录链接和现有前端写入。跨表汇总由平台计算，新增会议和待办按上述路由写入。

会议待办放在「04 横向统筹」，与「04.06 跨项目会议」相邻。三张原表的关联列分别指向固定目标，平台只归集恰好关联一场会议的待办。原表的历史待办文字可在会议详情查看，并在「全部待办」中保留。

等接入更多项目时，再评估是否迁移到统一会议主表。当前优先核对四张表的来源 ID、待办关联完整性和角色访问范围，避免为做跨项目统计复制同一场会议。
