# 海外运维协作平台｜智能体同步与归档说明

适用于会议、会议待办和知识资料。仅处理已有授权且来源可核对的内容。平台凌晨同步由服务器执行。智能体负责按本说明写入指定多维表并回读。

## 执行顺序

1. 识别对象类型、项目归属和稳定来源 ID。会议纪要默认链接到会议记录。只有明确要求作为独立知识资料归档时，才另外执行资料归档。
2. 按下方路由选择表。运行前读取表字段，核对实际字段名、类型、单选值、人员身份及关联目标。使用当前授权身份，人员 ID 必须由该身份所在飞书应用核验。权限、字段或归属有冲突时，保留源材料并报出待确认项。
3. 对每个来源 ID 串行执行。先精确查重，读取全部匹配页，再决定新建或更新。仅一个可靠匹配时，使用原 `record_id` 更新。多个匹配、归属变更或原记录辨认不清时暂停该条，由人工核对。
4. 第一次写入前，在「智能体同步台账」登记来源 ID、表 ID、提交键和附件清单。向业务表发起新建前，先把台账状态更新为「结果待核对」并回读，使中断后的任务知道可能已提交。新建回执丢失或重启时，按原键重新查询。核对到原记录后继续，仍查不到时保留原提交键并等待人工确认。
5. 写完后用 `record_id` 回读。日期按实际时刻、人员按稳定用户 ID、关联按记录 ID、网址按实际目标、附件按文件标识核对。只提交此次拥有明确更新依据的字段，保留未提供的值和人工维护内容。

## 智能体同步台账

在现有海外运维协作平台的飞书多维表内建立一张「智能体同步台账」。三类对象共用，每个会议、待办或独立资料各一行。由智能体维护，访问范围沿用现有已授权的管理员和智能体。首次配置后，保存台账的实际表 ID 和直达链接，后续按该 ID 使用。台账尚未建好、不可读写或写后无法回读时，暂停新建业务记录并汇报。

| 字段 | 类型与填写方式 |
| --- | --- |
| 台账键 | 文本，`对象类型/主来源键`，例如 `meeting/feishu-vc:示例场次ID`。先精确查重 |
| 对象类型 | 单选「会议」「待办」「资料」 |
| 主来源键 | 文本，首次关联后固定 |
| 来源别名 | 多行文本，一个已核实的完整来源键一行，匹配整行 |
| 目标表 ID、目标记录 ID | 文本，分别保存目标 `table_id` 和回读确认的 `record_id` |
| 业务提交键 | 文本，会议存 `Assistant Meeting ID`，待办存 `Assistant Action ID`，资料存 `Client Mutation ID` 对应的 UUID |
| 同步状态 | 单选「待写入」「结果待核对」「已回读」「失败」 |
| 附件回执、最近结果 | 多行文本。附件记来源文件标识或 SHA-256、上传状态、已回读的文件标识。结果记错误步骤或待确认原因 |
| 最近核验时间 | 日期时间，记录实际回读时刻 |

同一对象的所有入口共用这一台账，交给同一串行写入流程。已有来源别名先命中台账，随后使用表内原业务键。新增台账行回执不明时，按台账键回读核对；台账命中多行或别名指向不同记录时，暂停该对象并报告冲突。台账只存执行所需标识和回执。

| 字段 | 写入规则 |
| --- | --- |
| Meeting Title（会议名称） | 原主题，去掉录音文件后缀 |
| Assistant Meeting ID（助手来源会议ID） | 文本，首次建档时按下方来源规则填写；已存在的值原样保留 |
| Meeting Date（会议日期）、Meeting Time（会议时间） | 日期时间和文本。明确实际时区后换算北京时间，两个字段对应同一时刻，时间文本为 `HH:mm`。时区或时间无法核实时，暂停新建并说明 |
| Meeting Type（会议类型） | 单选。项目周期例会用「项目例会」，区域周期例会用「区域例会」，有明确审查对象用「专题评审」，面向客户用「客户沟通」，跨团队协调用「协调会」。证据不足时请人工确认，已有值继续保留 |
| Status（状态） | 单选「已开」「待开」「已取消」，按有证据的实际状态填写 |
| Summary（会议概要） | 保留主要议题、结论、决定和待确认项。区分已定事项与建议 |
| Participants（参与人） | 多人字段，使用飞书人员 ID。同名或身份无法核实时，记录待补人员 |
| Minutes Link（纪要链接）、Recording Link（妙记链接） | 分别填可核对的 HTTPS 地址，缺失时省略对应字段 |
| Priority（优先级） | 单选 P0、P1、P2。按已有明确要求填 |
| Action Items（待办事项） | 保留已有历史文本。新待办写到会议待办表 |

### 会议来源键

- 可核对飞书会议的具体场次时，用 `feishu-vc:<场次ID>`。周期会议使用能区分每一场的 ID。
- 只有飞书妙记时，用 `feishu-minutes:<妙记ID>`。同一场同时拿到会议场次和妙记时，新建使用场次键，妙记键登记为来源别名。
- 先收到妙记、后收到会议场次时，用飞书提供的明确关联核对为同一场，在台账里补场次别名，原会议 ID、业务提交键和已关联待办继续沿用。先收到场次、后收到妙记时，同样补别名并复用原记录。标题相同、会议时间相近只用于提示人工核对。
- 历史上已写入的前缀继续沿用。新来源无法提供稳定标识，或疑似同一场但对应关系无法确认时，先暂停写入，保留素材并汇报。

先查台账主来源键和别名，再按已核对的来源键查询三张会议表。首次接入历史记录时，可核对同一归属下的原纪要或妙记链接及开会时间。匹配唯一后复用旧记录，只在原来源 ID 为空时补写。会议回读成功后再写待办。

## 会议待办

一项独立可执行的事项写一条[会议待办](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblrUCVFXhyql7gJ)。

| 字段 | 写入规则 |
| --- | --- |
| Action Title（待办事项） | 写清具体动作和结果。讨论、提问和建议只有被明确列为行动时才录入 |
| Assistant Action ID（助手来源待办ID） | 用「会议记录中已固定的 Assistant Meeting ID:稳定事项ID」。首次拆分分配的事项 ID 持久保存，来源别名变化、文本润色和列表排序均沿用原待办键 |
| Assignee（负责人） | 使用已核对的飞书人员字段。只填明确承担人。仅给出团队或身份待确认时，在备注和结果里列出待确认项 |
| Due At（截止时间） | 按明确约定的时刻填写，统一按北京时间核对。只有日期时，将日期写入备注并提醒核对时刻 |
| Action Status（状态） | 新建的未完成行动使用「待办」。已有「进行中」「已完成」按已核对进展保留或更新 |
| Action Priority（优先级） | 只用明确的 P0、P1、P2。平台重要待办列出未完成的 P0、P1 |
| Action Notes（备注） | 填验收条件、待核信息或补充的日期要求 |
| 会议关联 | 按会议路由选择恰好一列，填已回读的会议 `record_id`。另外两列为空。回读时核对关联列及目标 ID |

按「助手来源待办ID」精确查重，唯一命中后先核对会议关联。保护人工已设定的负责人、截止时间、状态和优先级。源资料确认纠正这些字段时，将纠正依据随同步结果返回。

## 知识资料

一份可独立查阅的资料建一条记录。多个项目共用的独立资料只写一次。标准、目录或经验集本身是一份资料时，归档整份内容的入口。

| 内容归属 | 写入表 | 标题、类别、链接、附件、日期字段 |
| --- | --- | --- |
| 泰国项目专属 | [泰国 Araya 项目资料](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblCTyrV3BYSZkTv) | Document Summary（资料简述）、Document Category（资料类别）、Stored Link（存放链接）、Document Link（资料文档）、Date（日期） |
| 马来项目专属 | [马来项目资料](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblblTWYgpjMsaUh) | 同泰国项目资料 |
| 海外共用设备技术规格、维保规范 | [维保与技术资料](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblEg6Ql9waAVBVe) | Equipment Name（设备名称）、Document Category（资料类别）、Linked Document（关联云文档）、Attachments（附件）、Shared At（分享时间） |
| 海外共用的其他接维或运维资料 | [资料索引](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblIJiG3OE2QGTm8) | Document Title（文档名称）、Topic（主题分类）、Document Link（文档链接）、Attachments（附件）、Shared At（分享时间） |
| 区域周报、月报、办公制度等 | [区域协作站](https://vnet.feishu.cn/base/CID8b8V7CaCtKesWGFKcHTdqnlc?table=tblHa1UFDzN9doob) | 同资料索引。类别选「区域周报」「区域月报」「专题报告」「办公制度」「行政事务」 |

- 写清标题、类别和至少一个可验证入口。可直接访问的 HTTPS 地址填链接字段。文件上传到目标记录的附件字段，按原文件顺序追加。项目表的「资料文档」是附件字段。同名文件不能据此判断已上传，使用台账记录文件标识或内容哈希并回读。
- `Library Scope（资料范围）` 写 `project`、`shared` 或 `regional`。资料索引有 `Project（项目归属）` 时，共用资料选「海外」。区域协作站的篇章、阶段和目录留空。
- `Lifecycle Chapter（生命周期篇章）` 使用 `handover` 或 `operations`。项目筹备用文本阶段 `1`，目录字段 `Directory Category ID（目录类别编号）` 按下表填写。其它阶段用对应目录编号。无法核对目录时，先保留待确认项。
- `Discipline（专业）` 写一个明确专业，沿用平台选项「电气、暖通、弱电、消防、建筑、EHS、管理、综合」。无法确认时留空。备注只写影响使用的业务信息。
- 直接写表时只使用已存在的单选项。项目表的单选范围与资料索引不同。先读取该表的选项，按飞书返回的原始选项写入。找不到合适选项时停止该条，报出目标表和需要确认的类别。
- 资料使用 `Client Mutation ID（提交标识）` 去重。同一份资料的稳定来源键与 UUID 映射存入同一张「智能体同步台账」。优先取源文档标识或源系统的文件 ID，换标题、换目录或更新内容时沿用映射。新资料只生成一次 UUID v4，登记并回读后再写业务表，重试沿用。历史记录仅在原记录 ID 明确，或同一项目、同一资料类别下原链接唯一且标题相符时复用。平台表单已写过的提交标识原样保留，台账绑定原记录。

| 项目筹备子目录 | 目录编号 | 归档内容 |
| --- | --- | --- |
| 设备厂验 | `prep:factory-inspection` | 厂验计划、验收报告、见证记录、整改闭环 |
| 设备技术规格 | `prep:equipment-specifications` | 设备规格、参数和技术要求。共用设备表类别选「设备技术规格」 |
| 维保规范 | `prep:maintenance-standards` | 维保项目、频次及验收要求。共用设备表类别选「运维维保需求规范」 |
| 施工图及图审记录 | `prep:drawing-review` | 施工图、审图意见和图审闭环 |
| 招采与技术澄清 | `prep:procurement` | 招采文件、技术澄清及相关记录 |
| 团队组建与配置 | `prep:staffing` | 人力配置、岗位需求、团队组建材料 |
| 运维需求与方案 | `prep:operations-requirements` | 运维需求白皮书、前置方案及相关交付物 |

子目录编号由平台定义，写到资料记录的目录字段即可。目录与「资料类别」分别填写。项目筹备资料已确认阶段且子目录不明确时，可用 `handover:1`。国内案例沿用国内参考，需作为项目资料使用时等实际归属确认。

## 验收与回执

| 验收输入 | 预期结果 |
| --- | --- |
| 泰国施工图评审会议，带一条整改任务和一份独立施工图 | 泰国会议一条，待办只填泰国会议关联，施工图写泰国资料表且目录为 `prep:drawing-review` |
| 海外区域月报 | 区域协作站一条，主题分类为「区域月报」，篇章与阶段为空 |
| 同一来源按同一提交键重跑 | 保留原记录及附件，更新明确变化项 |
| 同一场先到妙记后到会议场次，或反向到达 | 有明确关联时，台账登记另一来源为别名，保留一条会议记录及原待办键 |
| 同一份资料改标题后重传 | 沿用台账中的 UUID 和业务记录 ID |
| 创建回执丢失或查到冲突记录 | 保留提交键，先回读，歧义条目待核，未确认的写入不报成功 |
| 只有团队、日期或模糊优先级 | 记录原有条件与待确认字段，人员和时间按已核对值填写 |

逐条返回来源标识、实际目标表、记录链接、已新增或更新结果、回读结果及待核项。可通过 `多维表地址?table=表ID&record=记录ID` 打开原记录。权限或字段不符时，报告发生在哪张表、哪一步。

## 平台凌晨同步

平台服务北京时间每日 02:00 开始读取飞书数据。覆盖知识资料、会议及待办、目录和录入字段、接维计划、已接入的调研项目、开办物资、人员储备跟踪、泰国和马来项目组织及重点事项。维护或服务重启后在 06:00 前补跑，失败模块间隔至少 15 分钟重试，成功模块当天跳过。已归档的旧任务表继续按原规则维护。
